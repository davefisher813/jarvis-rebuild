## Before it goes live (steps only Dave can take)

1. **Run migration `jarvis-core/supabase/migrations/0043_ai_spend_budget.sql`.** Until it runs, every AI call is refused ("AI paused. The spending limit could not be checked."): the limit fails closed. It was tested against a real Postgres 16 with `jarvis-core/supabase/tests/ai_budget.sh`; it has not been run against the live project.
2. **Check `AI_MODEL` and `AI_MODEL_WRITE` in Vercel.** The server prices calls from an exact model id table (`src/ai/aiBudget.ts`, price version `2026-09-29`). A model id that is not in the table is not called. Unset means `claude-sonnet-4-6`, which is in the table.
3. `AI_PRICE_MULTIPLIER_PERMILLE` is optional (default 1000). Set 1100 only if the Anthropic workspace uses US-only inference.
4. **Held calls are only released by a person or a job.** A call that may have been billed but never answered keeps its hold. Run `select ai_budget_reconcile_stale(interval '1 hour')` now and then; it is deliberately not automatic.

## Decisions still open (Dave's)

- **Budget period.** The $5 is "since the date it started". Nothing resets. It does not include the $5 already spent before this shipped.
- **The hold is a maximum, not the bill.** A call is held at its highest possible cost while it runs, so the balance can read a little low and a request can be refused with a few cents left. The screen says so.
- **Reply Coverage on long threads.** Conversations are read in at most three chunks; anything skipped shows "Answered 3 of 4 found".
- **Invitations.** Calendar access is read-only. "Accept" opens Google's page and may add the event to Jarvis; it never says the RSVP happened.

## What is proven and what is not

Proven by tests: the laws suite, the whole app suite, typecheck, lint at the 39-warning baseline, the production build, `build:legal` with no `public/` diff, the core package, and the budget functions under real concurrency.
Not proven: anything against real Gmail, real Google sign-in, real Supabase or PostgREST, a real phone, or the real model. Idempotency of "Add to Calendar" across two offline devices is not proven (see `emailSchedule.ts`).
