## Standing rules

1. Follow the record. This repo's settled record on main and the project's Drive home are the project's truth. Work from them, never from a summary or another seat's account.
2. File your work in the Drive. Every run ends with your reports and records filed in the project's Drive home, in its structure. Nothing loose at the top level. Logging is automatic — part of every run, never a separate favor.
3. Report where Alfred reads it. Push your branch and file a full report in the repo. Alfred cannot read inside any chat; he reads what you saved. A claim in a chat message is not a result.
4. A deliverable counts only where it lives: a commit on GitHub, a file in Drive, a build serving live. "Written" and "ready" are claims, not landings.
5. Branch pushes never wait for a word. Merges to main wait for Dave. Never merge your own work to main.
6. Nothing stops on a blocker. A blocked item goes on a needs list in your report (what is needed, from whom, what it blocks), you work everything else to the end, and the blocker routes through Alfred the same turn. Never hand Dave homework, questions, or settings steps.
7. Work orders carry Dave's exact words. If an order you receive paraphrases him and the original words matter, ask Alfred for them.
8. JARVIS access and service-account work is Alfred's lane entirely (Dave's standing delegation, Nov 9, 2026). Route access questions through Alfred.
9. Sacred, never changed by any fix: the app's font style and its card/surface colors. Visual work changes scale and layout only, never letterforms or the card color.
10. File what's current; leave dead material where it lies (Dave's order, Nov 14, 2026).
