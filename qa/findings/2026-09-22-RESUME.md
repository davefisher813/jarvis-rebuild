## The rulings being enforced

All in `jarvis-app/STYLING_CATALOG_V3.md`:

- **§AK One grey, ever (V5.2).** At most one run of secondary ink at regular
  weight per row. Weight alone is not a distinction (`--tx-2` and `--tx-3`
  are the same hex). Placeholder lines ("No category", "None") never render.
- **§AL The capsule.** `.pill-act` and `.row-act` are capsules on
  `--capsule-fill`, set with `background-color`, never the shorthand.
- **§AM The Colour Key.** Colour means something: green done, amber needs you
  soon, red late, sky an estimate, category colour on the dot only, brand red
  only for tappable things, white for a number with no state, grey for
  everything else once per row. Plus the Subtext Catalog picks F1–F7.

Laws that hold them: `src/laws/subtextLaw.test.ts`, `capsuleLaw.test.ts`,
`colourKey.test.ts`, `typeLaw.test.ts`, `astra.test.ts`.

## How to resume

1. **Re-audit the four sheets** the unfinished finder missed.
2. **Stylesheets first.** Apply the `pending` findings whose `fix_file` is a
   `.css`, one agent per stylesheet (never two agents on one file), running
   `npx vitest run src/laws/` after each, because many laws pin CSS text.
3. **Then code, one agent per file group.** Group `pending` code findings by
   the files each fix touches (union the files named in `file`, `fix_file`
   and the `fix` text) so no two agents edit one file. Each agent re-checks
   every finding against the *current* code and rejects any that the
   stylesheet pass already resolved.
4. **Use the shared primitives**, never a new class per screen:
   `.fact.date` (neutral date/time, small caps), `.fact.est` (estimate, sky),
   `.fact.good` / `.fact.warn` / `.fact.red` (done / due / late),
   `<b>` inside a fact line for a number with no state (white),
   `.fact.cat` + `.cd` for a category, `.input-hint` for a field note.
5. **Do not apply findings that delete or reword copy** without asking Dave;
   restyle instead. Several `pending` findings propose dropping a fact.
6. **Middots in strings (R6)** are the largest group and the least visible.
   Do them last.
7. Gate: `npx tsc --noEmit`, `npx vitest run`, `npm run build`, then the full
   visual audit (`DEMO=1 npm run build && npx vite preview --port 4173`, then
   `node tools/visual-audit.mjs`) and compare with the saved baseline.
